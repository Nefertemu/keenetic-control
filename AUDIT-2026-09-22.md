## Найденные пробелы, которые текущие тесты не выявляют

### 1. P1 — проверять пригодность резервной копии до восстановления

`BackupsView.swift:334–339` передаёт прочитанный текст непосредственно в
`Restore.compare`. Для старой незашифрованной копии допустим любой UTF-8,
включая пустой файл. `Restore.swift:66–108` считает отсутствие распознанных
объектов состоянием без списков и маршрутов: все текущие объекты попадают
в план удаления. Предпросмотр есть, но повреждённая копия не отклоняется.

Исправление: проверка формата и пригодности копии перед сравнением с отличием
корректной конфигурации без маршрутов от пустого/ошибочного файла. Тесты:
пустой legacy `.txt`, сообщение CLI, HTML и обрезанная конфигурация.
Наличие проверки повреждённого `.kcbackup` не закрывает старый формат.

### 2. P1 — защищать восстановление от устаревшего плана

`Restore.plan` не записывает исходное состояние объектов для повторной
проверки. `PlanVerifier.preconditionProblems` (`Plan.swift:101`) проверяет
только `domainListBaselines`. Если после предпросмотра пользователь изменит
подлежащий удалению список через веб-панель, старая команда удаления всё
равно применится. Свежая резервная копия сохраняет возможность отката, но
не предотвращает применение устаревшего решения.

Исправление: сохранять снимок затрагиваемых объектов для всех разрушительных
планов и сверять его непосредственно перед первой командой. Тест должен
менять список между предпросмотром и последним чтением и ожидать ноль записей.

### 3. P2 — проверять весь результат восстановления до сохранения

В `Restore.swift:124–127,168–170` удаление целых групп и изменение статических
маршрутов представлены только командами. `PlanVerifier` получает FQDN-группы,
но не статические маршруты; отсутствие удалённой группы тоже не проверяется.
Если команда проигнорирована без явной ошибки, восстановление может выглядеть
успешным. У Restore сохранение выполняется до проверки результата
(`RouterPlanExecutor.swift:140–149`).

Исправление: описывать ожидаемые группы, имена и маршруты в плане, проверять
их полное состояние и сохранять после успешной сверки. Тесты: тихо
проигнорированное удаление группы, добавление/удаление статического маршрута.

### 4. P1 — единый предел 300 для всех способов загрузки

Новая кнопка обновления соблюдает жёсткий предел. Но настройки позволяют
`chunkSize` до 1000 (`RoutersView.swift:248–253`), а ручной импорт и фоновая
сверка передают это значение в старый `Planner.planImport` без ограничения.
При размере 500 источник из 301 записи попадёт в одну часть
(`Plan.swift:377–395`). Размер части и потолок проверки также можно задать
противоречиво.

Исправление: общий эффективный предел для ручного импорта, фонового плана и
обновления; согласованная проверка настроек. Тесты всех путей на 300/301/601
и на старых сохранённых настройках с лимитом выше 300.

### 5. P2 — строгий разбор должен проверять всю строку источника

Воспроизведено отдельным запуском текущих Swift-парсеров:

| Вход | Текущий результат |
| --- | --- |
| `0.0.0.0 first.example.org second.example.org` | Только `first.example.org`, пропусков нет |
| `first.example.org INVALID-CONTENT` | Только `first.example.org`, пропусков нет |
| `10.0.0.0/8 192.168.0.0/16` | Только первая подсеть, пропусков нет |

`Domains.swift:14–18,128` отбрасывает хвост строки. Строгий загрузчик проверяет
массив пропусков, поэтому такой ответ считается полным. Если источник
перейдёт к hosts-строкам с несколькими именами, второй установленный домен
ошибочно будет считаться исчезнувшим.

Исправление: разбирать все допустимые hosts-алиасы либо отклонять неоднозначную
строку; после отдельного домена/подсети разрешать только комментарий. Добавить
проверку сохранности второго домена при таком обновлении.

### 6. P2 — точнее показывать состояние обновления

- При отключённом сохранении источник получает статус `.updated`, а пояснение
  о временном применении скрыто в свёрнутых подробностях
  (`DomainListUpdateController.swift:185–190`, `DomainListUpdateCard.swift:245`).
  Нужен видимый статус «Применено временно».
- При возвращении в раздел уже полученная ошибка снова свёрнута:
  `detailsExpanded` начинается с `false`, а `onChange` даты отчёта не срабатывает
  при создании нового экрана с готовым отчётом (`DomainListUpdateCard.swift:17–29,69`).
  Нужна инициализация по существующему результату.
- UI-тесты заранее раскрывают подробности и не нажимают кнопку обновления
  с настоящим обработчиком. Нужны сценарии действий с подставной сессией:
  запуск, ошибка, переход в другой раздел и назад, ввод граничных настроек.

### 7. P2 — выпускать сборку именно из указанного тега

Ручной workflow принимает `tag`, но checkout не использует это значение
(`.github/workflows/release.yml:19–21`). Название архива и релиза берётся из
ввода, а код — из выбранной ветки запуска. Проверка строки версии не доказывает
совпадение коммита. Если релиз без вложений, возможна публикация сборки из
другого коммита под существующим тегом. Это вывод из кода workflow и
[документации checkout](https://github.com/actions/checkout/blob/v7/action.yml),
где описан выбор ref по событию; выпуск в рамках аудита не запускался.

Исправление: checkout разрешённого тега, проверка SHA и существования тега,
передача имени через переменную окружения. Отдельно стабилизировать временную
папку тестов для проектов под File Provider и добавить независимую сетевую
проверку источников в CI. Сейчас оба сетевых сценария CI пропускает.

## Полезные новые функции после исправлений

1. **История операций по каждому роутеру.** Добавленные/удалённые записи,
   результат проверки, версия источника и переход к копии перед изменением;
   история сохраняется после перезапуска приложения.
2. **«Почему этот домен идёт через этот туннель?»** Поиск по домену/IP с
   объяснением совпавших списков, подсетей и порядка интерфейсов из прочитанной
   конфигурации. Фактическое прохождение трафика показывать отдельной проверкой.
3. **Выборочное восстановление.** Вернуть конкретный список или цепочку
   маршрутов с предварительным просмотром, опираясь на исправления восстановления.
4. **Переносимая зашифрованная копия с паролем.** Восстановление на другом Mac
   без исходного ключа из Keychain; текущий `.kcbackup` сам по себе его не заменяет.
5. **Быстрая отменяемая загрузка источников.** Ограниченная параллельность,
   отмена до записи и заметное предупреждение при аномальном сокращении списка.
   Обычное обновление по-прежнему выполняется одним нажатием.

Рекомендуемый ближайший этап: исправления восстановления, общий лимит и полный
разбор источников; затем тесты взаимодействий и история операций. Успешный
прогон существующих тестов не отменяет перечисленные пробелы их покрытия.

## Реализация рекомендаций — версия 1.3.0

Все семь групп замечаний выше исправлены. Исходные результаты аудита сохранены
как описание проверенного на тот момент коммита.

- Восстановление отклоняет непригодные копии, повторно сверяет затронутые
  объекты и проверяет полное ожидаемое состояние до сохранения. Проверяются
  удалённые группы, имена, статические маршруты и оставшиеся ссылки dns-proxy.
  Можно выбрать списки и отдельно восстановить содержимое, цепочки или
  статические маршруты. Неподдерживаемые команды не подменяются догадками.
- Общий предел 300 действует в ручном импорте, автоматической сверке,
  однокнопочном обновлении и создании отдельного списка. Старые настройки
  нормализуются. Предпочитаемый размер новых частей и допустимый размер
  готовой группы при восстановлении учитываются отдельно.
- Разбор источников обрабатывает все hosts-алиасы, отклоняет мусор после
  записи и IPv6 с локальной зоной интерфейса. Удаление при ручном обновлении
  тоже требует свежего полного источника.
- Загрузка ограничена тремя параллельными источниками; отмена прерывает
  чтение и загрузку до записи. Исчезновение больше половины набора и не менее
  20 записей требует подтверждения с повторной загрузкой и сверкой состояния.
  Временное применение видно сразу, ошибки остаются раскрытыми при возврате.
- История сохраняет по 100 операций на профиль, версии источников,
  изменения записей и флагов маршрутов, проблемы и ссылку на копию.
  Незавершённый результат не выдаётся за подтверждённый; очистка истории
  сохраняет выполняющиеся операции. Секреты команд и конфигурация в неё
  не записываются.
- «Поиск маршрута» объясняет правила для домена, URL или IP по прочитанному
  снимку. Политики устройств не смешиваются с глобальными маршрутами.
  Объяснение не выдаётся за измерение фактического трафика. Поиск доступен
  из бокового меню и палитры команд, учитывает смену роутера и снимка.
- `.kcportable` переносит копию на другой Mac с паролем: PBKDF2-HMAC-SHA256,
  600 000 итераций, AES-GCM и аутентифицированный заголовок. Есть проверка
  неверного пароля, повреждения, недопустимых параметров и размера файла;
  контрольный пример ключа рассчитан независимо через Python hashlib.
- Тестовая сборка по умолчанию вынесена из Desktop в Library/Caches.
  Релизный workflow проверяет тег до checkout и собирает его коммит.
  Отдельный workflow проверяет источники по расписанию. Распознавание текста
  в UI-тестах использует CPU: Vision на Neural Engine в этой среде мог зависать.

Ограничения остаются явными: старый открытый файл нельзя надёжно проверить
на потерю целого законченного блока без исходной контрольной суммы;
зашифрованные контейнеры аутентифицируются целиком. Восстановление исторической
группы больше разрешённого предела блокируется: автоматическая смена её ID
могла бы нарушить внешние ссылки. Поиск маршрута не выполняет скрытого DNS-
разрешения и не определяет активность маршрута по одной конфигурации.

Проверка настоящего окна дополнительно выявила необходимость разбирать
документированную форму статического маршрута «шлюз + интерфейс». Она добавлена
в общий разбор и проверку, чтобы действительная копия с таким маршрутом не
отклонялась; произвольные дополнительные токены и команды по-прежнему запрещены.
Для IPv6 поддержан также порядок «интерфейс + шлюз» из
[официального справочника CLI 5.0, раздел 3.94](https://storage.googleapis.com/docs.help.keenetic.com/cli/5.0/en/cli_manual_kn-2312.pdf#page=442).

Свежая конфигурация реального роутера выявила также контекстные строки
`ip route disable`: они относятся к предыдущему маршруту. Это поведение
подтверждено [обсуждением Keenetic 5.0](https://forum.keenetic.ru/topic/23888/).
Состояние «выключен» теперь сохраняется при разборе, импорте, экспорте,
сравнении и восстановлении. Связанные команды отправляются одной пачкой;
неуспешная пачка не повторяется поодиночке. Игнорирование отключения выявляется
до сохранения. Поиск маршрута показывает выключенные правила отдельно от
кандидатов среди включённых.

Для уточнения формата создана одна временная защищённая копия через настоящее
приложение. Предел хранения на время проверки увеличен с 10 до 11, затем
возвращён к 10; удалена только созданная проверкой копия. Все 33 исходных файла
копий остались на месте с прежними SHA-256. Конфигурация роутера только читалась.

Финальная проверка истории выявила утечку параметров пользовательской ссылки
через сообщение о неудачной загрузке. Диагностические строки теперь очищаются
от логина, пароля, query и fragment URL перед сохранением в историю и журнал;
старые записи очищаются при чтении. Исходные адреса загрузки не меняются.
Добавлены проверки неудачного отчёта, файла журнала, старой истории и обычных
сообщений без URL.
